# OpenGL ES games on the S20 (libredwood-eagl)

**State (2026-11-12):** Angry Birds Space and Leo's Fortune run and draw (user-verified). Commit 09b9956.

## Why games were black or crashed
iOS 16's OpenGL ES (OpenGLES.framework -> AppleMetalGLRenderer) runs on Metal. It makes its shaders with
`-[MTLDevice newFunctionWithGLESIR:inputsDescription:functionType:]`; the function's bitcode is Apple's private
"GLIR" (header u32 3 + counts, a compact LLVM-like stream with air.* metadata, no `BC` magic), read only by Apple's
AGX compiler (AGCStreamTokenBitCodeGLIR). Our Metal (RedwoodMetal: AIR -> NIR -> panfrost) cannot compile it, so the
first pipeline is refused. Open-source Metal implementations do not read GLIR either. Dead end; do not go back.

## What runs instead
`userland/src/eagl_app.m` -> `/redwood/lib/libredwood-eagl.dylib`, inserted by the kernel (kern.exec_inject /
etc/inject.conf) into the programs named in build.sh `EAGL_APPS`:
- EAGLContext's methods are replaced. `initWithAPI:` (2 or 3) makes a Mesa OSMesa context, always ES 3 (ES 2
  programs run unchanged; blits need 3). Share groups share Mesa objects.
- iOS's exported gl* functions read `tpidrro_el0[30]` (TSD slot 30) and call `entry(P[4], args...)` at
  `P + 0x20 + offset` (offsets: `src/eagl_slots.txt`). `+setCurrentContext:` puts our table there (generated by
  `mkeagl.py` from eagl_app.m: every entry calls Mesa's function of that name) and makes the Mesa context current.
- `renderbufferStorage:fromDrawable:` gives the bound renderbuffer the layer's pixel size (bounds x contentsScale,
  RGBA8 or RGB565). `presentRenderbuffer:` blits it, flipped, into one of four IOSurface-backed textures (Mesa's
  `glEGLImageTargetTexture2DOES` takes an IOSurface ID), waits for the GPU, and sets it as `layer.contents`. The
  surface on screen is never written. CPU readback is the fallback if the GPU path fails.
- Any other EAGLContext method logs once (`redwood-eagl: ... not had here`) and returns 0.

**Never link `-framework OpenGLES` into it:** the gl* names then bind to Apple's, and every call loops back forever
(game at 100% CPU, nothing drawn).

## Adding a game
Its executable name (`CFBundleExecutable`) into `EAGL_APPS` in build.sh (space-separated), rebuild root.apfs.
Without a reboot: `sysctl -w kern.exec_inject="$(sysctl -n kern.exec_inject);/redwood/lib/libredwood-eagl.dylib NAME"`
(sysctl is /var/jb/usr/sbin/sysctl), then relaunch the game.

## Debugging
- Log lines `redwood-eagl:` on the console (`curl http://10.77.0.2:8080/log`).
- Frame grab: `touch <app data container>/tmp/eagl-shot`; within 30 frames `eagl-shot-WxH-STRIDE.bgra` appears beside it.
- Dev loop: build eagl_app.m as in build.sh, `codesign -f -s -`, scp to /private/var/tmp, point kern.exec_inject at it.

## Open
- Only named games; ES 1 fixed-function games not covered (Mesa ES profile has no ES 1).
- PVRTC compressed textures (common in old iOS games) are not decoded.
- Leo's Fortune draws at 1280x960 and scales itself up (looks stretched): the game, not this.
- Possible next: a fence instead of glFinish per frame; inject into all apps that link OpenGLES.
